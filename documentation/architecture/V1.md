# SUPERNet V1 Architecture

## Client

`Applications -> Android TUN -> Packet Core -> Scheduler -> Path Transports -> Gateway`

The Android client owns VPN interception, network discovery, deterministic scheduling, health state, and tunnel lifecycle.

## Gateway

`Client paths -> Session -> Reassembly -> Internet routing`

The gateway maintains one logical session across multiple physical paths.

## Failure behavior

A path transitions through `ACTIVE -> DEGRADED -> UNSTABLE -> FAILED`. Recovery uses `RECOVERING -> TESTING -> ACTIVE` with hysteresis so intermittent links do not flap.

## Honest performance model

SUPERNet can aggregate independent links and hide individual path failures. It cannot exceed the practical capacity of the available links and cannot maintain Internet connectivity when every path is unavailable.
